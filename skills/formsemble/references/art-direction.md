# Make the visual direction specific to this product

## Translate taste into visible decisions

Treat adjectives as prompts for interpretation. Establish what they mean in this context:

| User language | Possible concrete interpretation | Evidence to inspect |
|---|---|---|
| Premium | Deliberate composition, restrained emphasis, consistent craft, excellent content and feedback | Alignment, hierarchy, imagery, state detail, typography |
| Professional | Clear responsibilities, predictable controls, useful density, credible claims | Main task, labels, grouping, consistency |
| Playful | Friendly interaction, meaningful surprise, expressive details | Tone, illustration, motion, feedback without distraction |
| Calm | Reduced competition, clear progress, stable layout | Salience, spacing, interruptions, error recovery |
| Bold | A distinctive hierarchy or expressive visual gesture | Contrast of scale, composition, repeated product signature |

These are hypotheses, not universal mappings. Premium can be bright, dense, or playful when the product demands it. Do not turn "premium" automatically into dark backgrounds, gold accents, glass panels, gradients, or oversized empty hero sections.

## Read references as evidence of preference

Inspect supplied screenshots and visual references with an available image-reading tool before extracting their traits. Filenames, alt text, and an unseen reference are not visual evidence. If you cannot inspect a reference, state the limitation and use only the information actually provided.

For each supplied reference, distinguish:

- What the user explicitly likes or dislikes.
- What you infer: hierarchy, spacing, type character, density, navigation, imagery, motion.
- Which traits transfer to this product, and why.
- Which content, assets, or patterns should not be copied.

If comments are ambiguous, extract a small trait set and test it on the user's actual screen. Do not create a collage of incompatible references. Respect supplied brand constraints and asset permissions; do not invent a new brand when the request is to improve an existing one.

## Explore meaningful alternatives only when useful

For a consequential new direction, compare two hypotheses using the same representative content and task. Change structure or behavior where appropriate, not only color:

- Action-first versus discovery-first information hierarchy.
- Editorial composition versus a compact instrument-like workspace.
- Image-led reassurance versus information-led confidence.
- Direct manipulation versus guided selection.

These are examples, not mandatory categories. Describe a benefit, a tradeoff, and suitability for each. Recommend one; proceed with a reversible slice unless the user's unresolved preference truly determines the direction. Respect an already selected direction without reopening the same decision every session.

## Define a small visual grammar

Specify the choices that materially create coherence:

- **Composition:** primary focal area, meaningful grouping, alignment, reading path, information density.
- **Type:** role hierarchy, readable sizes, line lengths, weight relationships, language support.
- **Color:** semantic surfaces, text hierarchy, action/status roles, actual contrast against backgrounds.
- **Space and shape:** spacing rhythm, containment choices, radii, borders, elevation only where they explain relationships.
- **Imagery:** subject, crop, aspect ratio, content responsibility, quality and fallback behavior.
- **Motion:** purpose, trigger, feedback, interruption, and reduced-motion alternative when relevant.
- **Interaction:** focus, hover, selected, disabled, pending, error, and success treatments as applicable.

Use existing tokens when sound. Change them intentionally when the chosen direction warrants it, then check affected shared components. Do not introduce an entire token framework for one local fix.

## Give the product one meaningful signature

Choose a memorable behavior or visual motif tied to the domain: a distinctive way to reveal a recommendation, a status relationship, a useful map/list transition, or a recognizable composition. Keep the primary controls familiar enough to understand. Novelty must not make ordinary navigation cryptic.

Use a substitution question: if the brand name and nouns were swapped for an unrelated product, would every design decision still seem equally justified? If so, strengthen the relationship between the product's task and its hierarchy, content, or interaction. This is a self-check for specificity, not a scientific measure of originality.

## Diagnose visual weakness before restyling

| Observed issue | Investigate first | Avoid the reflex |
|---|---|---|
| Everything competes | Relative emphasis, content priority, action hierarchy | Add more colors or larger shadows |
| The screen feels generic | Domain-specific information and meaningful interaction | Randomize the font and palette |
| The screen feels empty | Missing decision context and composition | Fill it with invented statistics |
| The screen feels crowded | Grouping, redundancy, progressive disclosure | Hide essential information everywhere |
| It feels inconsistent | Shared tokens, repeated control semantics, state styles | Patch every instance independently |
| It feels beautiful but unclear | Labels, affordances, expected outcomes | Explain the UI in chat instead of repairing it |
| It feels lifeless | Feedback and appropriate emphasis | Animate every element |

## Evaluate actual craft

Inspect the rendered result with real or clearly labeled representative content. Check focal hierarchy, alignment, optical balance, line wrapping, content density, image crops, repeated spacing, borders, empty areas, and state consistency. Judge a focused screen at its real size, not only a reduced montage.

Do not ban cards, familiar fonts, gradients, or rounded corners categorically. Require a reason for their use and inspect whether they serve the product. Do not equate originality with obscurity or visual noise.
